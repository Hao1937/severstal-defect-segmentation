## 日常流程

1. 在 Mac 修改代码与配置，同步设计、决策或实验文档。
2. 完成相关检查和 neat-freak 收尾后提交，推送到 GitHub；需要向训练端交付时，再推送到 Legion 裸仓库。
3. Legion 没有正在运行的本项目任务时，拉取新提交并开始实验。
4. 每次运行保存代码 commit、实际配置、初始化来源和结果，放入独立运行目录。
5. 将小型指标和选定图像回传 Mac，在实验记录中解释结果；大权重和完整预测留在 Legion。

Mac 提交后上传 GitHub：

```sh
git push origin main
```

`main` 已设置上游为 `origin/main`，在该分支执行 `git push` 也会推送到 GitHub。两个远端独立，向 GitHub 推送不会自动同步 Legion。

需要同步训练端时：

```sh
git push legion main
ssh legion 'git -C /home/wyhao/projects/BigData pull --ff-only'
```

训练期间不更新训练工作副本；Mac 可以继续编辑、提交和推送，待本轮结束再拉取。需要并行跑不同版本时再增加工作副本。

## 文件与版本

- Git 保存源码、配置、依赖说明、数据获取与划分方法、文档和精选结果。
- 数据集、权重、环境、完整预测和运行日志由 `.gitignore` 排除。
- 小改动直接提交 `main`；探索较大改动使用短分支，检查后合回。
- 默认在 Mac 改源码。若在 Legion 紧急修改，先提交到独立分支，再由 Mac 拉取合并；不通过整目录覆盖回传。
- 回传使用指定文件或目录，不使用带删除选项的双向镜像。实验目录包含 E 编号与运行编号。

裸仓库与工作副本的分工参考 [Git 官方说明](https://git-scm.com/book/en/v2/Git-on-the-Server-Setting-Up-the-Server)。

## GitHub 连接排障记录（2026-10-26）

首次推送先报 `Error in the HTTP2 framing layer`，临时改用 HTTP/1.1 后仍报 `SSL_ERROR_SYSCALL`。实查 Clash 运行规则发现，前置的 `DOMAIN,github.com,DIRECT` 覆盖了后面的 GitHub 代理规则；默认连接和显式使用本地代理端口均在握手阶段断开，而 `api.github.com` 可访问。

已通过当前订阅的「编辑规则」将该条改为 `DOMAIN,github.com,Default Proxy`，保留其他规则。保存后核对运行规则，默认 HTTPS 返回 200、证书验证通过、协议为 HTTP/2；原命令 `git push -u origin main` 随后成功。没有设置全局 Git 代理，也没有关闭证书校验或永久降级 HTTP 协议。

此修改保存在订阅自定义规则中，维护入口见 [Clash Verge 官方说明](https://www.clashverge.dev/guide/rules.html)。后续再遇到连接错误，先核对实际命中的路由；仅切换 Git HTTP 版本无法修复被强制直连的路径。
